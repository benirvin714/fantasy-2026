## Hard rules
1. **Read-only on Sleeper.** Never execute any write action against the league (waivers, lineups, trades, drops). The current MCP is read-only-by-construction, but if write tools ever appear: show the exact action and get explicit confirmation first, every time.
2. **No stale player analysis.** Training data on player values/depth charts/ADP is outdated. Any player-facing claim must be grounded in live Sleeper MCP data or current web search; if unverifiable, say so — never guess.
3. **Everything scored in THIS league's format** — never hand over generic/standard-scoring takes without translating.
4. **Docs track reality, in the same commit as the work.** A handoff doc that contradicts itself is worse than no doc: it reads as authoritative and sends the next reader down a dead end. Concretely, when you ship anything:
   - Move **`progress.md`**'s `Last updated:` stamp to the date you're actually committing. If you edited the body, the stamp moves. No exceptions.
   - Anything in **Next steps** that the work just completed comes **out of the list** — don't leave "not yet built" next to a section describing it working.
   - **One canonical dashboard URL: `https://hbgbs.irvinfamily.com/site/`.** (The phone Draft Aid is a *separate* site on a separate host, `https://draft.irvinfamily.com` — not a page of the dashboard, and not an alternative address for it.) The `hbgbs-hq.pages.dev` address still resolves and is still gated, but it appears in prose **only** as "the old URL also works" (currently just the Files entry below). If you're adding a link, use the custom domain. Files that carry it today: `progress.md` (header), `CLAUDE.md` (below), `.claude/commands/brief.md`, `.claude/commands/scout.md`.
   - Same discipline for the design of record, `plans/valuation-and-scouting.md`: new behavior gets its numbered subsection, and a claim that stops being true gets corrected rather than layered over.

(`OTHER_LEAGUE_ID` in the same file belongs to the other-league tab and is unrelated to the HBGBs renewal.) The Draft Day page (`/site/draft.html`) **syncs live with a Sleeper draft**: paste a draft ID, hit connect, and it marks picks off itself (`?draft=<id>` overrides the stored ID), raises an on-deck prep panel at ≤3 picks away, and fills a roster grid as your picks land. `?at=<pickNo>` replays a finished draft to that pick. Specs: `plans/valuation-and-scouting.md` §1.15–§1.17.
- `data/site/team-environment.json` — all 32 offenses by projected points scored, with a league-format starter core and pass share. Powers the **Offenses** rail, which sits to the LEFT of the draft board, always expanded (no toggle), sticky like the target rail. Three columns (offenses | board | targets) need a 1540px viewport; under that it stacks below the board. Rebuild: `node scripts/build-team-environment.mjs` (`--offline` skips the 5MB ESPN PDF fetch and uses the committed snapshot `data/raw/clay-team-projections.json`). Context only, never an input to draft-$ or edge. Spec: `plans/valuation-and-scouting.md` §1.19.
- **Two leagues, one set of pages.** `site/index.html` and `site/rosters.html` render whichever league is active. `site/league-switch.js` resolves it (`?league=` for a visit, then this browser's choice, then `DEFAULT_LEAGUE`), publishes `HQ_CONFIG.active` with that league's four JSON paths, and stamps `<html data-league>`. **Nothing downstream may build a data path itself.** Two declarative hooks: `[data-league-switch]` gets the switcher chips, `[data-league-only="hbgbs"]` is **removed** rather than hidden — a hidden panel still fetches and still errors into a box nobody sees. It loads at the **end of `<body>`, above the renderers**, with a small inline stamp in `<head>` so the palette can't flash; putting the whole thing in `<head>` and deferring to `DOMContentLoaded` raced against `app.js`, which runs earlier. Spec: `plans/valuation-and-scouting.md` §1.25.
- `site/rosters.html` — **the roster room**, the middle page of the four (`in-season HQ | roster room | draft day | other league`). Every team in the league as a scouting object: an optimal lineup under this format's slot shape, per-slot and per-position rank against the other nine, the tradeable surplus on each bench, the six-season owner dossier, and trade proposals that ship **only where both lineups rise**. Its league table carries the **live standings** (fetched from Sleeper on each load, cache-busted) and sorts on them, falling back to the projection while every record is 0-0 and saying which in the panel. **Clicking a row expands it in place** to that team's roster and loads the scouting panels below. Rebuild: `node scripts/build-roster-room.mjs [--league=hbgbs|pit]` -> that league's `roster-room.json`, twice daily for **both** leagues via the `nfl-daily-events` task (step 8). A league with no dossier file gets no Owner tendencies panel and a live **Moves** column (completed transactions this season) in place of the trade-appetite chip; the page branches on the data, not on a league key. The build **refuses to run until every roster has players**, so it is a post-draft tool by construction — which also means it will refuse on every scheduled run between a league renewal and that season's draft. That is correct, and the task is told to report it and carry on. Specs: `plans/valuation-and-scouting.md` §1.20, §1.22.
- `site/league.html` + `site/league.js` — **the other-league tab**, the fourth chip in the nav. Paste any Sleeper league id (or its URL) and it renders **that** league live from Sleeper: format read, a scoring diff against the HBGBs over the union of both leagues' keys, standings with the playoff cut, any roster in that league's own `roster_positions` shape, this week's pairings, and the full draft by round. League selection is `?league=<id>` > this browser's last connection > **`OTHER_LEAGUE_ID` in `site/config.js`** (a default, not a binding — currently `1401363352046825472`); disconnect writes a `"none"` sentinel so it sticks. That is a **third** league id, on its own schedule — a stale one is harmless, the tab just opens on last year's league. **It reads no local JSON, publishes none and runs no valuation, on purpose** — `draft-board.json`, `roster-room.json`, `faab-market.json` and the owner dossiers are all scored in HBGBs settings and keyed to HBGBs roster ids, so pointing them at another league would be analysis-shaped fiction (hard rule 2). No build step. Spec: `plans/valuation-and-scouting.md` §1.24.
- **The standings are no longer on in-season HQ.** That featured slot holds **my roster** (same table, `site/roster-table.js`, shared with the roster room). Don't re-add a standings panel to `site/index.html` — it moved on purpose, see §1.22.
- `data/site/player-news.json` — one dossier per rostered player, powering the **click-a-player-name dialog on both HQ and the roster room**: the dated events naming that player, the scouting brief with sources, ADP commentary, availability. Built offline from three published feeds: `node scripts/build-player-news.mjs [--league=hbgbs|pit]` (`npm run build:player-news`, `npm run build:pit`). **Two fields on the shared inputs are gated per league** because they are not facts about a player: an event's `league_notes` (who rosters whom) and `adp_commentary` (draft-room strategy that names one league's owners). After any change to what the leagues share, re-scan the built file for rival owner names — that is how both leaks were caught. Front end: `site/player-news.js` (one delegated `[data-pid]` listener, lazy fetch on first click).

## MCP notes
- Sleeper MCP: 13 read-only tools. No transactions endpoint and no free-agent-pool endpoint — supplement with Sleeper public REST (`https://api.sleeper.app/v1/...`, read-only GETs).
- If the Sleeper MCP is unavailable, commands must say so and state what's missing — never fabricate league data.
- **The Sleeper MCP is registered at user/local scope on Ben's machine, NOT in this repo** (there is no `.mcp.json`), so it exists in the local CLI and desktop app and **does not exist in Claude Code on the web** — a remote session has claude.ai connectors instead, and none of them is Sleeper. Verified 2026-09-04: zero Sleeper tools in a web session's registry. What follows from that:
  - In a remote session the four commands above that open on `get_nfl_state` / `get_league_rosters` hit the no-MCP branch immediately. Fall back to **Sleeper public REST** (read-only GETs, cache-busted) and say that is what you did.
  - **The remote container's egress proxy blocks `api.sleeper.app` outright** (measured: `connect_rejected`), so REST is not a fallback there either — a web session cannot reach Sleeper at all by any route. Anything needing live league data must be run locally, or read in the browser by the dashboard's own client-side fetches (`site/app.js`, `site/rosters.js`, `site/league.js` all fetch Sleeper from the page, which is why they work while the session it was built in could not).
  - Making the MCP work in web sessions would mean it being a **remote** server (an http/sse URL added as a claude.ai connector). A stdio server (`npx …`) cannot be reached from there, and adding it to `.mcp.json` would not help while the proxy blocks the destination.
